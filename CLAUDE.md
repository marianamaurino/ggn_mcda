# Claude Code: standing instructions (ggn_mcda)

GoGreenNext WP6, PhD of Mariana Mauriño, ISGlobal. Multi criteria decision analysis (MCDA) of greening
priority in Malta and Klagenfurt, with the citizen survey weights. Split from `ggn_analysis` on
2026-11-26 (history of the `mcda/` folder kept; older history, from before files moved into `mcda/`
on 2026-11-04, stays in `ggn_analysis`). The HIA lives in the sibling repo `../ggn_analysis` and reads
the saved MCDA score files from the shared data folder; this repo never reads anything from the HIA.

Folder details and file rules: `mcda/CLAUDE.md`. File index (main, sensitivity, exploratory,
instructions): `mcda/README.md`.

## Folder map

- `mcda/`: all MCDA code (kept as a subfolder so every `here::here("mcda/...")` path works unchanged)
- `R/`: shared helpers, copies from `ggn_analysis/R/` (`theme_lancet.R`, `read_survey.R`).
  Keep the two copies in sync by hand if one is changed.
- `data/` -> `../ggn_analysis_archive/data`, `output/` -> `../ggn_analysis_archive/output`
  (symlinks, not in git; the same data and outputs the HIA uses). `mcda/exposure` and
  `mcda/accessibility` are symlinks into the archive as well.

Paths: `here::here("data/...")`, relative to this repo root (`.here` file). No absolute paths.

For Malta the reallocated population version is always the canonical one. The Malta HIA reads the
protected backup `data/malta/malta_mcda_processed_realloc_pre_nov19.rds` (6 Nov 2026 score): never
overwrite or delete any `*_pre_*` backup. Before overwriting a score file, back it up with a dated suffix.

**Spec master copy.** `mcda/MCDA_paper_results_spec.md` is the master. The user's claude.ai project copy
can be stale: when the user edits the spec, diff against HEAD and flag any reverted decisions; after a
spec change, give the user the full merged file. Dated history of every decision: `mcda/CHANGELOG.md`.

**Current criteria decisions** (main vs sensitivity; do not switch back without the user asking; full
history in `mcda/CHANGELOG.md`):
- Available weight rule: score a cell if its criteria carry at least 80% of the weight (spec 4.2).
- Not eligible cells: Malta airport and port, water (majority Urban Atlas class rule), both cities.
- Green per person (Malta): own E2SFCA (`mcda/malta_e2sfca_newpop.R`, NSO population, Gaussian sigma
  5 min, cut 15 min). ATGreen = sensitivity only.
- Walking time: own OSM routing, shared filter `mcda/walk_filter.R`, class 32000 excluded, origin
  inside green = 0, continuous with p98 cap. ATGreen = sensitivity only.
- Street greenery (Malta): tree canopy in a 10 m street buffer, linear (spec 3.6). The farmland class
  rule variant was dropped on 2026-11-26.
- Traffic: OSM road type, 3 classes (K3), tunnels excluded. K2, K5, CAMS-REG, OpenTransportMap =
  sensitivity only.
- Klagenfurt equal weights: 1/6 per criterion, NO2 and PM2.5 1/12 each (2026-11-25).

## Writing rules

- **No em dashes, anywhere**: notebooks, docs, code comments, reports and chat replies. Use a colon,
  comma, parentheses or a new sentence. Hyphens are fine.
- **Methodology prose**: do not rewrite or add prose unless asked. If code changes make existing prose
  wrong, leave a `# TODO: update text` marker and flag it.
- **Sanity checks for new variables**: at minimum a `summary()` and a map or histogram.
- New tasks from the user are often pasted instructions: save them verbatim in `mcda/instructions/`
  with a dated file name when the instruction asks for it.

## R coding style

- Pipe: always `%>%`, never `|>`. Tidyverse by default.

## Shared server: do not overload the CPU

Shared 128 core server. Every `Rscript`/`rmarkdown::render` must be launched with
`OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 FLEXIBLAS_NUM_THREADS=4 MKL_NUM_THREADS=4 nice -n 10`.
For headless knits also set `RSTUDIO_PANDOC=/usr/lib/rstudio-server/bin/quarto/bin/tools/x86_64`.
No parallel workers above 4. One heavy job at a time; check `uptime`/`ps` first.

## Making changes

- Deletions over 20 lines: present a plan first and wait for approval.
- Additions and small edits: proceed if the intent is clear.
- Out of scope bugs: flag, do not fix without asking.
- Do not change definitions before asking.
- Commit or push only when asked. The server has no GitHub login: the user pushes from their terminal.
